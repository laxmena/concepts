Hooks: when they run

A hook is a command a repo asks the agent to run at a fixed moment, such as before a tool call. Only of repos commit one, so every share below is among repos that have hooks.

What this cannot tell you

  • It counts what is in the files, not whether the file helps an agent. A short file can be worse than a long one.
  • Public repos that GitHub code search indexes, as of . Private repos are not here, and of the repos are small or personal, which is why popular repos are shown beside them.
  • Your token count is an estimate: characters divided by , the median characters per token across the census files, measured with an o200k tokenizer. It is approximate, not Claude’s tokenizer, and it leaves out imports.
  • Overview sections, directory trees and the /init line use the same rules as the census. Commands, imports and “don’t” rules in the checker use simpler matching, so treat those three as approximate.
Method, in two sentences

The census sampled public repos through GitHub code search by file size, weighted each repo by how likely it was to be picked, and drew 95% intervals by resampling repos. Only counts and shares were kept, with no file text, repo names or paths.

Numbers are on the neri repository. The derived numbers are shared under CC BY 4.0.
