Quantization

Storing a model’s weights in fewer bits, so it is smaller and cheaper to run, at the cost of rounding error.

  • Most model weights are stored as 16-bit numbers, and that is more precision than they need.
  • Quantization rounds each weight to the nearest of a few levels and keeps a small whole number plus a shared scale.
  • Fewer bits means a smaller file and less memory to read for every token.
  • The price is rounding error, and it grows fast below about four bits.

What just happened

  1. Take a group of weights and find the largest. It sets the scale: the largest weight lands on the top level. At bits there are levels, the whole numbers from −7 to 7 and zero in between.
  2. Divide every weight by the scale and round to the nearest whole number. Store that small number, plus one 16-bit scale for the group.
  3. To use a weight, multiply its number by the scale. The gap between each blue dot and its orange bar is the error. At bits it is about of a typical weight.

The rule, and what real methods add

The scale is s = max|w| / (2b−1 − 1). A weight is stored as q = round(w / s) and read back as q × s. This page uses that plain rule, called absmax or round-to-nearest, on a made-up row of 64 weights.

Methods used in practice pick the scales and the rounding more carefully. GPTQ rounds each weight while adjusting the ones not yet rounded to cancel the error, using second-order information from a sample of data. The page also ignores the activations, the numbers the weights are multiplied with, which quantization can hurt as well.

Where you meet it

Quantization is why a model that was trained on a rack of GPUs can run on one card or a laptop.

  • Open models are shared as 8-bit and 4-bit files, and the file size in the name is the number of bits on disk.
  • QLoRA fine-tunes a 4-bit base model by training small LoRA matrices on top of it.
  • The KV cache can be quantized as well, to fit more people on one GPU.

Where it breaks

Weights are not all the same size. Here one weight is a typical weight. With one scale for the whole row, that weight sets the step for everyone. Switch the row to One large and watch the orange bars disappear.

Small groups cost storage. Every scale is 16 bits, so one for every 8 weights makes bits per weight and for the model, against . Real large models have a few very large values in the same dimensions again and again, and Dettmers and others found they break plain 8-bit rounding. In that paper the large values are in the activations, not the weights. This page puts one in a weight to show the mechanism.

Check yourself

Going from 8 bits to 4 makes the model half the size. Does the error double?

No. Eight bits give 255 levels and four bits give 15, so each step is about 18 times wider. On this row the error goes from under 1% to about 14%. Size shrinks in a straight line and error does not.

A weight is 0.001 and the scale is 0.01. What is stored?

0.001 / 0.01 is 0.1, which rounds to 0. The weight is stored as zero and its value is gone. This is what the large weight does to its neighbours: it makes the scale big.

Why not give every weight its own scale?

A scale is a 16-bit number, so it would cost more than the weight it protects. One scale per 32 weights adds half a bit to each, so a 4-bit model is really 4.5 bits.
