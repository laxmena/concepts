LoRA

Low-rank adaptation. A way to fine-tune a large model by training a tiny add-on instead of the whole thing.

  • Fine-tuning changes every weight, so you train and store as many numbers as the model has.
  • LoRA freezes the weights and learns the change as the product of two thin matrices.
  • The rank r is how thin: a sum of r simple patterns, each one a column times a row.
  • If the change really is simple, a small r captures almost all of it.

The formula, the start, and what LoRA does not do

The layer computes x · (W + (α/r) · B A). W is frozen. B starts at zero and A starts random, so the update is zero at the start and training begins from the pretrained model. The α/r factor is a scale so that changing r does not change the size of the update much. After training, B A is added into W, so the model runs at the same speed as before, with no extra layers.

The grids use a fixed update built so its best low-rank approximation is known exactly. The best rank-r approximation keeps the r largest singular values (the Eckart–Young theorem). LoRA never computes that. It learns B and A by gradient descent, and the best rank is the most it could reach.

For a real layer the update is not a fixed grid. Whether it is low rank is an empirical question that depends on the task. The next section tries a spread-out update.

Where you meet it

Fine-tuning a large model normally needs memory for a gradient and optimiser state for every weight. LoRA needs them only for B and A, and a LoRA add-on is small enough to store and swap per task.

  • Hu and others (2021) report that for GPT-3 175B, LoRA can cut the trainable parameters by about 10,000 times and the GPU memory needed by about 3 times, while matching or beating full fine-tuning on the tasks they tried.
  • The Hugging Face PEFT library implements LoRA and related methods for transformer models.

Where it breaks

LoRA only helps if the change you need is close to low rank. Here is the same slider on a different update, one whose strength is spread over many patterns. Switch the kind of update.

At rank the spread-out update keeps only of its strength, against for the low-rank one, and it needs about rank 6 to reach . The grids are made up to show the idea. Real updates sit somewhere between these two. Biderman and others (2024) compared LoRA with full fine-tuning on code and maths and found LoRA learned less on those harder targets, and also forgot less of the original model.

Check yourself

A weight matrix is 1,000 by 1,000. How many numbers does LoRA train at rank 4?

4 × (1,000 + 1,000) = 8,000, against 1,000,000 for the full matrix: 0.8%.

Why start B at zero?

Then B A is zero, so the model begins exactly as the pretrained model. Training moves it away only as far as the data pushes it. If both started random, the first step would already be a random change to every layer.

Doubling r doubles the trainable numbers. Does it always double what you can express?

No. In the low-rank example rank 1 already keeps 75% and rank 2 keeps 94%. Later ranks add very little because the update has little left in those patterns. In the spread-out example each rank adds a similar share.
