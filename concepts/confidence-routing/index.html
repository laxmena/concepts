Confidence routing

Let a cheap model decide when it is sure, and pass the rest to an expensive model or a person. How agents with a decision model save money.

  • Run the cheap model first. If its confidence reaches a threshold, accept its answer.
  • If not, hand the decision to a strong model, or ask a person.
  • The threshold sets the trade: a higher bar costs more and lets fewer mistakes through.
  • It only works when “sure” means something, which is what calibration checks.

What is assumed

The cost ratio and the strong model’s accuracy are assumptions, and you can change the ratio above. The cheap model is the calibrated toy from the Calibration page, so what it says is how often it is right. Real strong models are not right at a flat rate: they fail more on the same hard cases the cheap model is unsure about, and a person who is asked has a cost and a delay of their own.

Where you meet it

  • Agent gates: before a tool runs, a small local decision model checks the call. If confidence is at least the threshold the action runs, and if not the agent stops and asks the user. AWS’s example uses a threshold in application code and suggests stricter bars, 0.90 to 0.95, for risky actions such as deleting files.
  • Cascades: the REFLEX paper uses Jev as the fast layer in front of a strong LLM. The authors report 95% task success with 72.7% fewer strong-model calls on a frozen 100-task benchmark. They also report limited advantages over a cheap generative cascade on some outside tests where ordinary routing was already accurate.

Check yourself

You raise the bar from 90% to 95%. What happens to cost, to accuracy, and to the share the cheap model keeps?

The cheap model keeps fewer decisions, so more go to the strong model and cost rises. Accuracy rises a little, because the decisions that remain are the ones it is surest about. Here the share drops from 38% to 24% and the cost goes from 64.5% to 78.7%.

Why does an overconfident model hurt a routing scheme?

It admits decisions it is less sure of than it claims. The cost looks good, because fewer decisions reach the strong model, but the mistakes go up in exactly the place nobody is checking.

Why use a different bar for different actions?

The price of a mistake differs. Looking up the weather can run at a low bar. Deleting a file or changing a database should need a high one, with a person in the loop when the model is unsure.
